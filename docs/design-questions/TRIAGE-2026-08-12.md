## ✅ 1. DQ-058 — double-attach: diagnostic, type error, or legal?

- **Blocks:** `future/components/lifecycle-disposal.spec.ts` (last red; file
  promotes on ratification + implementation).
- **Recommendation (= the entry's own):** **Option 1** — a runtime
  `component:duplicate-attachment` diagnostic through the existing
  `validateAttachment*` channel, keyed on behavior identity + slot name.
  Explicitly out of scope: de-duplication (the diagnostic reports, it does not
  fix), and option 3's `stackable` metadata until a genuine stacking case
  appears. Option 2 (a sixth type axis on `Component`) costs more than the
  mistake it prevents and is blind on the dynamic path.
- **Premise check:** the attachment-validation channel exists and already
  carries per-slot diagnostics; behavior values are stable object references,
  so identity needs no new machinery beyond a derived identity for `compose`.
- **Cost:** small (one registration map on the component's attachment state,
  one diagnostic code, one spec un-gated).

## ✅ 2. DQ-092 — `Idle` and the reserved `Initial{waiting:false}` slot

- **Blocks:** `future/result/wire-mapping.spec.ts` (last red; closing it
  finishes the entire `result/` lane).
- **Recommendation (= the entry's own):** **Option 1** — `Idle` means "not
  started, and not going to start unless asked" (a manual/deferred query
  before its first trigger). Decode of `Initial{waiting:false}` becomes
  `Idle`, not `Loading`.
- **Premise check:** the plan's Decision 7 explicitly permits this exact
  change to the frozen Slice-1 fixtures as "a future, explicitly
  wire-versioned change (`Idle`, …)" — so implementing it does not violate
  the wire pin, it exercises the one sanctioned door. §2.5's "slot is
  reserved" note should land in the same change.
- **Cost:** moderate (core `Result.idle`/`isIdle`, one decode-row change with
  a wire-version note, builder/`all`/`match` arms, fixture update under the
  sanctioned exception).

## ✅ 5. DQ-014 — `Resume.fragmentAction`'s home and signature

- **Blocks:** `future/streaming/server-fragments.spec.ts` spec 5 (last red;
  file promotes on landing), M11b item 4.
- **Context change since the entry was written:** its deferral awaited
  "DQ-011 resolving the Resume audience split" — DQ-011 has since been
  ratified, as M9 sequencing (SPI blocked on the permissive package). The
  audience-split reason to wait is therefore no longer live.
- **Recommendation (the entry's own lean):** **Option 1** —
  `ServerRoute.fragment(...)` defines the server half (it genuinely is a
  `ServerRoute` handler: schema'd args in, `{html, manifest}` +
  single-flight loaders out), with a small client caller that pairs with the
  existing `Resume.mountFragment`. Interim option 3 (document the manual
  composition) stops being needed the day this lands.
- **Cost:** moderate (one ServerRoute constructor + client caller composing
  `invokeSingleFlight` and `mountFragment`; the spec's assertion is that one
  round trip returns fragment + revalidated loader snapshots without a
  second loader run).

## ✅ 6. The M9 ⇄ M10.4 knot — build `@affe/permissive`?

- **Blocks:** M9 (SPI freeze — ratified DQ-011 makes it *blocked on* this
  package), `future/resumability/adapter-spi.spec.ts`, and per item 4 above
  it is also the natural home for the MCP adapter.
- **Recommendation:** commit to building the permissive package as the next
  major milestone after the current DQ backlog clears: auto-capture +
  universal codec + reference plugins bundled as one configuration (all
  three now exist in core as of M10.1–3), doubling as the external SPI
  consumer M9 requires. Scope v1 to what exists — defer the store-proxy
  layer.
- **Cost:** large (a package boundary, workspace wiring, the Chromium
  Qwik-parity demo from the M10 acceptance list) — hence a milestone, not a
  slice.
